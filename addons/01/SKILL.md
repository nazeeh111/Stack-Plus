# 01

Activate once for this chat, including follow-ups and resumed work, until disabled. Own useful capability selection, execution and verification so the user need not invoke specialists. Preserve the user's host, model, effort, scope and authority. Continuous means adapting during active work; it does not start background work or authorize self-editing. Keep routine work direct.

## Understand the outcome

Inspect the actual inputs, artifact and constraints. Work backward from the result to the decisions, transformations and checks that determine its quality. Identify important unresolved needs, dependencies and uncertainties, including contributions outside the apparent discipline. When prior decisions matter, read the shared Home and relevant owning notes and follow their sources; resolve stale or conflicting evidence.

## Compose by contribution

Consider skills, native tools, connected plugins/MCPs and recorded runtimes together. Describe the needed contribution before choosing its name. Use current host metadata and actual interfaces; names, brands, popularity, aliases, category placement and result order do not establish fit.

Compare combinations by coverage, compatible inputs/outputs, verification, prerequisites and cost. Each method should add a useful decision, transformation or check. Prefer complementary contributions over redundant advice; compare a simpler direct route or a materially different combination when the choice matters. Resolve conflicting methods against the task and evidence. More methods do not establish quality.

Use the overlapping work, domain and artifact views to discover candidates across disciplines. Categories are navigation, never exclusive routes or prescribed combinations. When names or neighboring methods are unclear, consult [method families and discovery](references/method-families.md). Its helper searches fresh metadata and optional bounded bodies; separate `--need` queries preserve distinct contributions. Drop filters for unfamiliar, new or unclassified capabilities. Native plugin/tool discovery remains separate from this local catalog.

Read the selected complete SKILL.md and needed support, inspect its current interface, then apply it to the actual work. Resolve handoffs through actual host IDs or relative bundled support; an upstream mention alone is not an installed capability. Check enablement and readiness for the required operation, rather than assuming an installed method or old success proves current execution. Cards are description-bound navigation, not proof of a current body, runtime or permission.

For an unavailable connection, use an existing authorized alternative when it meets the outcome. Never retry the same denied operation through another tool or side effect; identify the control and seek a scoped remedy. Complete independent work. Select and apply find-skills yourself for a concrete method gap or justified better specialist; source review, prerequisites, trials, actual use and existing authority still govern acquisition. Do not install a weak match merely to fill a category.

## Execute, check, reconsider

Sequence dependencies and parallelize independent work when useful and authorized. Use the orchestration method when coordination itself is substantial. Give workers clear outcomes, inputs, owned artifacts, authority and checks; keep one writer per artifact and verify handoffs. Reuse productive workers; independent reviewers receive raw results without a favored conclusion. Work directly when delegation adds little.

At substantive follow-ups, stage changes, failed checks or new evidence, reassess both the remaining needs and the combination. Keep valid methods and artifacts; add, replace or drop contributions as their value changes. Refresh affected capability metadata. Reconcile changed inputs and stale derived outputs before continuing. An initial plan is revisable, and a failure does not automatically justify another reviewer or identical retry.

Check integration between methods and the whole intended result. Execute the deliverable and inspect its actual outputs; loading a skill, a confident report or printed success is not application or correctness. Reconcile uncertain external effects before retrying. Avoid routine catalog rescans, fixed skill rotations and reopening settled choices without evidence. Stop refining when further work offers no meaningful improvement within scope; deliver the completed work, not advice alone unless requested.

For substantial work, keep the contribution map in the existing task entrypoint: selected paths/revisions, what each changed, resulting artifacts/checks and unresolved needs. Distinguish discovery, instruction delivery, worker-reported use and independently verified outcomes. Keep routine replies free of receipts. Save useful durable decisions/corrections in the owning shared note with readback; skip transcripts and duplicates, and keep generated host memory separate.

Retain 01's active/disabled state and actual path with the objective, authority and next action. After resume or compaction, reread 01 if its instructions are absent, then recover the current route and unfinished checks. Respect later disabling; a saved activation does not enable 01 in an unrelated chat. Ask only for material missing decisions or authority, and report failed checks and real limits honestly.
