# Native formal-verification workflow

This is the complete selected pstack method and complete linked statechart leaf.
Exact originals, source hashes and narrow native diffs are in `SOURCE.json`.
The source `create-formal-verification-skill`, `maintain-formal-verification-skill`
and `statechart` names refer respectively to the installed authoring, maintenance
and TLA state-machine skills. Read the complete sibling method when it is needed;
source slash notation is not an installed command by implication.

Read the operative [statechart method](support/statechart/METHOD.md) for its full
procedure. Its source entry is archived as `upstream/support/statechart/ORIGINAL-SKILL.md`,
with the original source coordinates and exact bytes recorded in `SOURCE.json`.
Only the bundle root `SKILL.md` is a discoverable entrypoint.

Use actual native shell/file/planning tools and preserve the user's model and
effort. This method does not install pstack, change providers, set up another host,
create cloud agents or grant commit/publish/spending/credential authority. There
is no automatic Mise, Java, TLC or renderer bootstrap. For TLA+, discover the
existing statechart runtime and use its recorded Node/Java/TLC entrypoints.
The support leaf keeps the statechart method and native no-bootstrap binding;
its source tests and scripts are retained, not all newly commissioned here.

TLC's breadth-first check uses local Java RMI sockets. A network-denied Mac
execution can reject that bind. Consult the runtime's recorded accepted execution
route; the isolated Linux check preserves the same scripts, jar and algorithm.
Do not treat a different search algorithm as equivalent graph or shortest-path
evidence. If no accepted route is available, keep the verification incomplete.

Create or update a verification skill only for the concrete owning repository
and requested target. Inspect its current instructions, skills, dirty work and
supported discovery path first. In Codex a repository-owned `.agents/skills/`
skill can hold the workflow; preserve existing files and merge a scoped addition.
For another host verify its supported project-local path before writing. If no
project skill discovery is supported, retain the explicit local instructions and
report that they are not registered. Do not install global project hooks, proof
jobs, policies or new skill catalogs merely because this method is available.

Keep the original obligations: choose the consequential promise, map every
model/proof step to real code, distinguish an atomic action from multiple code
steps, retain bounds and assumptions, and make each property fail on a deliberate
broken variant of the guarded code. Reproduce a model counterexample against
actual code. A bounded model plus replay is not a proof of all implementation
behavior. If no suitable code verifier is available, label generated-input tests
as tests, as the original method requires.

Preserve product code and unrelated dirty bytes. Scratch mutations belong in an
owned disposable copy and must be removed/restored before handoff. Maintenance
runs the old check first, examines every covered-code change and keeps bugs,
model drift and intended promise changes separate. Never weaken a promise to get
a green result. Advance the sync commit only after the real current code and
verification agree. For uncommitted work, record the actual base commit plus
explicit dirty-source hashes; do not pretend the commit alone covers those bytes
or invent a commit. A blocked check keeps its previous confirmed generation.

Keep full runnable commands, paths, source/tool versions, raw results, the real
mutation and restoration evidence with the owning task. A generated skill that
has not been followed and successfully challenged is a draft. Toolkit acceptance
of a small fixture does not verify a future project's promises or automatically
create its project-local skill.
