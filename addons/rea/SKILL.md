# REA software analysis

Use REA when the question depends on a shipped application, package or compiled artifact. It is separate from Craft Anything and from RAEA's video/game renderer. Resolve the requested target explicitly; a nearby app or saved fixture is not the user's target.

Read [the native runtime binding](NATIVE-BINDINGS.md) for the installed entrypoint and accepted operations. The private pinned CLI is the default route. Installation adds no global MCP server, decompiler, browser, model or background service. Existing connected REA tools may be used through their actual supported schemas.

For an authorized PE/ELF artifact, use the recorded recipe's `native-exports` command and inspect the artifact identity, export table, coverage and limits. Retain complete Evidence and use `summary` for a bounded follow-up. Static exports do not establish implementation behavior, runtime reachability or security enforcement.

JavaScript/Electron analysis exists in the original CLI, but the isolated `inspect` route currently fails during worker cleanup because macOS denies process-table inspection. It is not commissioned. Do not repeat that failed lane or drop isolation to make it pass. Saved-Evidence summary is independently supported; consuming partial Evidence does not turn its failed producer into a success.

Choose the smallest relevant view or trace after an overview. Preserve exact Evidence IDs and input digests; absence in a selected page is not application-wide absence. Recheck changed inputs and reuse valid matching work. Reconstruct requested behavior with the normal coding tools, then verify the implementation separately.

Other REA formats and runtime workflows are available in the installed CLI but have separate prerequisites and effects. Inspect the selected command's help and matching versioned source before use; establish its actual readiness within the user's task and existing authority. Installing REA does not establish native decompilation, live instrumentation, device access or environment-building acceptance.

The complete [upstream method](upstream/ORIGINAL-SKILL.md) and its eight guides are retained as source references, not additional installed skills or authority. Their mutable acquisition, client-setup, paid-evaluation and secret-handling defaults are not activated by this binding. Preserve the user's host, model, effort, permissions and spending scope. Never run upstream setup to replace this managed installation incidentally.

Finish with the evidence-backed answer or verified deliverable, unresolved limits and cleanup of owned sessions/processes. Keep detailed Evidence with the task and only useful durable conclusions in the owning knowledge note.
