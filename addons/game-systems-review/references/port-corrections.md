# Scope and admitted-rule corrections

An independent source review of the first prepared port identified two concrete issues. The original upstream files remain unchanged; SOURCE.json and the adaptation diffs record the active corrections.

1. **Preserve the negative expertise boundary.** The original game-designer heading “What This Agent Must NOT Do” introduced exclusions. The first port changed that heading to neutral “Expertise scope” while retaining imperative bullets, which could reverse their meaning. The active heading is now “Outside this expertise scope,” explicitly says these are exclusions, and preserves the implementation, art/audio, final narrative, technology and scope-approval exclusions. References to original departments are mapped to the owning work and the user's actual authority, not installed dispatch targets.
2. **Read rule-bearing Edge Cases.** The upstream load optimization excluded Edge Cases on the premise that no checklist consumed them. That premise conflicts with its own Phase 2 floor-bypass, death, timing and stacking checks; Phase 4 combined-state scenarios; and the game-designer definition of Edge Cases as minimum/maximum states and degenerate strategies. This was inherited, not an introduced regression. The native loader now includes Edge Cases and Cross-References, admits rules under any heading, reads small GDDs in full and requires full-read fallback or NOT ASSESSED when complete relevant rule coverage cannot be established. This intentionally changes the source optimization to satisfy its substantive review contract; it does not add another workflow or project requirement.

The edge-only raw fixture supplies ordinary admitted sections in both GDDs and an unreferenced rule override under one Edge Cases section. It is input for a targeted independent recheck. Package tests check its placement and provenance; they do not establish an actual reviewer result. First-version review reports and freeze evidence stay with the owning task and are not rewritten.
