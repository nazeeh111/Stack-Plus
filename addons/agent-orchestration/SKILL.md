# Agent orchestration

Keep the user's chosen lead, model and effort. Assign worker roles by needed capability and evidence, without a fixed brand hierarchy. Workers inherit by default; use a different model or variant only when the user explicitly names that override. A request to research orchestration does not authorize model calls or configuration changes.

Read the relevant [host mechanisms](references/hosts.md) before selecting workers. Inspect actual tool parameters, available model IDs, variants and concurrency limits. Prefer existing native workers; a skill cannot create provider access or transfer another host's tools. Distinguish requested model, configured preference and effective run identity. Report identity as unverified when the host does not expose it.

For a lead that must combine results, delegate bounded tasks and retain final synthesis. Transfer user-facing control only when a handoff is intended. Give each worker the needed inputs/context, expected output, evidence/checks and owned scope. Keep one writer per shared artifact; integrate and inspect worker outputs rather than treating agreement as proof.

Keep concurrency, retries and model steps proportionate to the work and existing usage authority. Preserve provider/data boundaries. In applications, aggregate worker usage through supported run accounting; mixed-model token totals do not establish monetary cost. Stop failed or redundant branches. Report unavailable models and material tool/feature mismatches; never silently substitute models or widen permissions. Continue independent useful work while a material replacement decision is pending.

Use existing LangGraph or the OpenAI Developers Agents skill when a produced application needs durable state, explicit branching or an SDK-owned loop. They do not replace routine native coordination, and an installed offline runtime does not establish online provider readiness. Add no framework or service without a concrete project need. Evaluate quality, time or cost gains against the actual task; promise no universally best pairing or future compatibility.
