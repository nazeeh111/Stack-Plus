# Original research engines

The selected additions are the full pinned ShinkaEvolve program-search engine and AI Scientist v3 study pipeline. Their original methods and support files are packaged separately from on-demand executable runtimes. See [preparation and entrypoints](RUNTIME_GUIDE.md), [source review](SOURCE_REVIEW.md) and [native binding](codex-transport/README.md).

Shinka's original runner completed a bounded CPU acceptance through the native binding: three generations, two actual current-model subscription requests, original evaluator/archive, two baseline-to-candidate parent branches across initialized islands, independent geometry validation and fresh evaluator replay. Migration policy ran with zero transfers. Optional embeddings, meta-analysis and prompt evolution were disabled; no novel-research or general efficiency claim follows.

The reusable general Shinka CLI is source-complete and passes no-model planning/contract checks, but its separate evaluator probe was denied by macOS `sandbox-exec` before Python execution. That entrypoint remains conditional until the denial has a scoped supported resolution and a real evaluator check passes. The earlier bounded original-run acceptance does not close this later integration gap.

AI Scientist's full production runtime is still conditional. Its original Linux candidate/evaluator RPC, repaired readonly evaluator broker mount, actual role isolation, source staging and a bounded native shell/apply_patch transport smoke passed. A full six-phase attempt stopped before inference on readonly-copy formatting; a subsequent attempt accepted one native request but interrupted it on timeout with inference/usage uncertain. Verified private raw archives and failed receipts were retained. Its complete task-drafting→investigation→ablations→final evaluation→posthoc→paper pipeline has not yet passed. Method packaging, dependency presence and transport tests do not establish that readiness.

Use only a source-closed durable runtime prepared by the toolkit's explicit on-demand recipe. Keep pinned source, licenses, dependency/image hashes, exact authority patches, originals/diffs and run receipts. Do not execute a public source checkout or acquire the upstream default multi-provider image as an installation shortcut. The currently supported Codex binding requires an exact reviewed0.169.0 client; an older toolkit bootstrap client does not satisfy that prerequisite. Prefer an existing compatible client; any private compatible acquisition needs its own official pin/rights evidence. No global CLI/config/profile changes.

Every native dispatch dynamically validates the actual current host session/turn model and effort, requires ordinary ChatGPT subscription status, builtin OpenAI and no paid fallback. No host credentials are copied/mounted/exported into research containers. Other hosts need independent supported model/effort/authority bindings; a model-agnostic engine does not make a guessed launcher compatible.

Scientific methods remain evidence-bounded. Shinka's original evaluator imports candidates in-process, so its output needs independent validation and a separate execution boundary. AI Scientist must preserve its original qualified sealed evaluator/candidate separation and final-data accounting. Source-imposed auth staging, unsafe launch defaults, tool branding and generated controller-side setup are handled explicitly by reviewed host bindings; original licenses and honest experiment/model lineage remain intact. Never call a substitute loop or fabricated phase receipt full-engine acceptance.

`python3 integrations/research/codex_client.py --client /absolute/existing/codex` verifies an existing compatible client without inference or auth/config changes. If none exists, `--acquire --state /fresh/private/directory` acquires only the independently pinned official Darwin ARM64 client into that directory. Source/asset/rights provenance is in `CODEX-CLIENT.json`; this leaves the toolkit bootstrap and global CLI unchanged. The scientific-image recipe is a dependency prerequisite, and full AIS campaign acceptance remains a separate gate.
