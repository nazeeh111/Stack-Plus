# Native Codex research transport

This executable replaces only the model-request transport for the pinned ShinkaEvolve and Agentic Scientist engines. It preserves their original search/study orchestration. It is not a substitute research loop and does not establish scientific effectiveness.

Current evidence: the original Shinka runner completed a bounded three-generation CPU circle-packing run through this transport, with two actual current-model requests, original archive and two baseline-to-candidate parent branches across initialized islands, independent numerical validation and evaluator replay. Migration policy ran with zero transfers. Optional embeddings, meta-analysis and prompt evolution were disabled for that acceptance. AI Scientist's full production workflow remains incomplete: its container flag also controls qualification/final topology, auth staging and container paths. A native CLI substitution alone does not resolve those coupled requirements. Do not activate it from transport or dependency tests.

The current native CLI contract was reviewed against `openai/codex` tag `rust-v0.169.0`, commit `d32063f96c2dff1dc96af839b3952abb6acfeda4`. Version drift fails closed. The first-party CLI manages its existing ChatGPT login normally; this adapter never opens/copies/mounts/exports credentials and never sets a forced login policy. Native `login status` output is captured, compared to the exact ChatGPT marker and discarded, since other status modes can contain a masked key. Paid/provider environment variables and remote executor configuration are excluded by an allowlist. There is no paid, provider or model fallback. An external deliberate login change between status and dispatch remains a non-atomic race; this is not an authenticated spending control.

The exact reviewed `codex-cli 0.169.0` is an on-demand prerequisite. Use an existing compatible client first, or acquire the official matching release into a private research runtime with source/artifact/license provenance and a task-local PATH. The public toolkit bootstrap may supply an earlier client; installing the toolkit alone does not satisfy this prerequisite. The transport does not upgrade, downgrade or replace the global CLI, alter profiles, download a client automatically or claim readiness with an incompatible version.

Before every request, `current_context` rereads only native session identity/provider and latest turn-context model/effort from a caller-supplied metadata reference. Thread and expected current turn must match. The reference never supplies a model default; observed cached values are ignored. A changed parent turn requires a refreshed reference. Optional caller model/effort arguments must exactly match that live native context. Transcript text is not retained or copied.

The per-run named permission profile starts with minimal system reads, adds only declared public read/write roots and the exact trusted CLI executable needed for sandboxed filesystem helpers, then denies the auth directory, SSH/AWS/Docker directories, Docker socket paths, task-private roots, trusted receipts and configuration. Model shell network and Unix sockets are disabled. Source roots are untrusted; unrelated MCP/apps/plugins/hooks/computer/delegation/code-mode and memory features are disabled per invocation. Existing system/user exec rules are not ignored. Native shell, apply_patch and image filesystem access use the CLI sandbox context. A caller can explicitly allow native remote web search, which is separate from shell networking and must be reported per study.

Model output is untrusted. Private request/completion receipts retain exact native argv, policy, context identity, prompt digest and measured token usage. Dollar cost is unknown, not fabricated zero. Raw native events stay private. Process time/output are bounded and only the transport's own process group is terminated on failure. Any missing final answer/usage or failed native turn is a failure.

`--check` verifies version and current metadata only. It makes no inference call and does not imply authenticated or scientifically validated readiness. `--plan` prints the concrete command/policy without inference. Normal invocation performs the native subscription status check immediately before launching.

The manifest schema is version1 with `context_reference`, `workspace`, `read_roots`, `write_roots`, `deny_roots`, `receipt_dir` and `timeout_seconds`; optional `web_search` is `disabled` or `live`, and `max_output_bytes` caps native logs. Paths are absolute owner-controlled task configuration; receipts and manifests must stay outside model-writable roots. All roots must exist. Use fresh private receipt directories. Upstream `--allow yolo` is accepted as a compatibility request but maps to the manifest's scoped policy and never becomes a native permission bypass. `--allow read-only` removes model write grants.

Shinka's supported `SHINKA_HEADLESS_COMMAND` can point to `python3 /absolute/path/transport.py --manifest /absolute/task/manifest.json`. Agentic Scientist native shell paths accept `HEADLESS_BIN`, normally through a small task-owned wrapper supplying the manifest; its direct Python command builder also needs a maintained transport adaptation. Its default credential-copying agent containers and hardcoded Headless provider are not activated by this adapter. Phase-specific grants must preserve sealed task/evaluator/final data boundaries. Do not grant an entire study directory merely to make a failing phase pass. Full-engine runtime and scientific acceptance remain separately evidenced.

`apply_engine_patches.py SOURCE --archive NEW_PRIVATE_ARCHIVE --bash /absolute/reviewed/bash` checks all11 full file preimages/results before editing and saves originals, diffs and a receipt. Python is parsed and shell syntax is checked with the supplied Bash in an empty environment. The explicit binding patches cover the original prepared model-dispatch seam, a trusted immutable TeX image, readonly evaluator broker metadata, rejection of unsupported controller-side setup.py, user-directed suppression of optional tool watermark/default tool authorship, and source-proven readonly-copy staging compatibility. Staging changes only newly owned results/scratch copies after source/destination alias preflight; canonical source stays readonly and executable bits/bytes remain preserved. Scientific gates and third-party licenses remain intact. Drift and archive reuse fail. Use a fresh readonly source generation; an older installed package does not change when a different source tree is patched.

`executor_relay.py` is an optional one-request authenticated loopback WebSocket-to-stdio transport. It adds no model or filesystem tools and performs no path mapping. Its no-model Linux executor handshake worked, but the first allowed managed file read was rejected by bubblewrap namespace controls under the tested Docker policy. No bypass or alternate execution fallback followed that denial. Explicit programmatic External policy subsequently passed approved no-model isolated-container and stock app-server remote-only thread/settings gates. One approved bounded External native subscription smoke subsequently passed actual remote command execution, native apply_patch and independent sealed/auth/socket controls. The relay records ConnectionClosedError during orderly host shutdown with child exit0; that limit remains visible. Original trusted evaluator RPC hit a macOS-to-Linux Unix-socket mount limitation; an ordinary Linux controller then passed the unchanged original RPC and named launch witness with readonly broker metadata and owned cleanup. These are scoped transport/control checks. The complete original six-phase campaign remains unaccepted. Its reviewed optional Python runtime pins `websockets==17.4`.

Verification: `python3 -m unittest discover -s tests -p test_research_transport.py -v`. Tests include exact patch preimage refusal with recoverable originals and the installed first-party no-model native sandbox on macOS, checking allowed writes, private/symlink reads, sealed ancestor renames, TCP and a synthetic Docker-style Unix socket. A separately authorized bounded live probe exercised actual native shell and apply_patch with the current parent model/effort; task-local receipts report its result. These checks prove the tested mechanics, not universal sandbox security or research quality.

The Linux controller uses `engine_bridge.py` only after the original shell role builder prepares its mounts. A private regular-file queue and private ownership ledger stay outside all model/evaluator/candidate mounts. `docker_guard.py` admits exact reviewed immutable images and a deliberately narrow canonical bind grammar, supplies finite preparation limits, and validates private launch ownership before cleanup/agent exec. Agent-only no-socket policy is separate from the trusted original evaluator RPC. `native_dispatch.py` defaults to no inference until its caller explicitly enables an authorized turn; it revalidates actual container controls, dynamic native metadata and effective remote-only thread settings. The files are reviewable implementation, not a full-engine readiness claim. Direct provider-driven conceptual-figure command pipelines are not commissioned and fail explicitly if required.
