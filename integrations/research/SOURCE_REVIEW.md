The selected pair adds concrete execution capabilities beyond scientific-method instructions. Shinka supplies evolutionary program search, population archives, parent/inspiration lineage and island migration. AI Scientist supplies task qualification, investigation, baselines/ablations, separated final evaluation, posthoc analysis and evidence-grounded manuscript stages. Neither replaces independent experimental design, claim validation or peer review.

Shinka's original runner, sampler, patching, archive and evaluator completed three generations on its shipped 26-circle packing task through the native transport. Two actual requests inherited the current parent model/effort dynamically. The unchanged baseline scored 0.9597642169962064; both generated candidates scored 2.517157287522862. Independent checks verified array shapes, finite values, boundaries, nonnegative radii, pairwise non-overlap and the reported sum; a fresh original-evaluator replay matched. SQLite records two baseline-to-candidate parent branches across initialized islands. Migration policy ran with zero transfers; no linear generation0→1→2 chain or actual island transfer was observed. This is a functional acceptance of a bounded CPU task. Embeddings, meta-analysis and prompt evolution were explicitly disabled, so it does not reproduce every paper setting or establish novel research, generalization, metric-gaming resistance or reported efficiency.

Shinka's local evaluator imports candidate code in its evaluator process and inherits environment by default. The acceptance used a separately scoped native evaluator sandbox with per-job outputs, no account/network/Docker access, then independent numerical checking. Its textual mutable-region boundary is not an OS sandbox. Subscription price was unknown; upstream zero-cost displays must not be read as billing evidence. Its optional WebUI path checks need correction before exposure.

AI Scientist's qualified contracted path has genuine sealed candidate/evaluator containers and final-data boundaries. The legacy shipped circle-packing example does not establish those guarantees. The reviewed route retains its full original Linux controller, original candidate/evaluator RPC, and original six scientific stages. The host alone owns ordinary subscription authentication and official app-server control; all model tools run solely in independently verified role containers. No model container receives the Docker socket or host auth. Eleven exact file adaptations preserve the production evaluator, scientific criteria and source originals while handling native transport, controller setup refusal, readonly broker metadata, optional output branding and owned-copy staging.

The first official managed remote-executor route hit a real bubblewrap namespace denial. No privileged/unconfined/bypass remedy was applied. The official programmatic External sandbox policy was subsequently reviewed and delegated only to the explicitly verified Docker boundary. Actual remote-only no-model role gates, a bounded native shell/apply_patch smoke, and original Linux evaluator/candidate RPC plus named evaluator launch witness passed. A macOS-created evaluator Unix socket had failed with Errno95; retaining the ordinary controller entirely in Linux resolved that path without changing the scientific RPC. Exact CPU dependencies, Git, TeX and required Poppler validation were installed offline into a reviewed immutable image; original ICLR fixture compilation passed, without representing a study paper.

Full AIS scientific acceptance remains incomplete. An original six-phase campaign stopped before inference on frozen-copy formatting. After the reviewed staging repair and actual first-role delivery gate, a fresh campaign accepted one native task-design request but was interrupted on timeout; inference and usage remain uncertain, not zero. Both attempts' raw evidence is retained; the latter verified archive exported successfully and owned runtime cleanup completed. No investigation, ablation, final evaluation, posthoc or manuscript success is claimed. Explicit role-local original-method indexes and unchanged original prompt hashes prove delivery; privacy-preserving event receipts do not prove complete method file reads. Actual workflow application and scientific claims require real artifacts and independent review.

AutoResearchClaw's whole pipeline can use ACP/acpx, so rejecting it as API-only would be incorrect. At this pin its ACP client drops model/max-token/temperature/JSON-mode requests and uses persistent session state; its no-tools restriction is prompt text with approve-all. Current literature verification can assign perfect integrity when all checks are skipped, publication can restore the original bibliography after heavy verification removal, and empty/error registry cases can skip manuscript verification. The default generated-code subprocess is not a filesystem sandbox. These are practical integration and scientific-validity gaps despite the workflow's breadth.

autoresearch's original training and measurement code is tightly tied to CUDA, NVIDIA hardware and FlashAttention. Its read-only data-preparation boundary is an instruction, and the repeated validation objective has no separate sealed final evaluation in the original loop. A Metal/CPU fork could be a useful distinct adaptation, but a substituted trainer or tiny mock loop would not establish original-workflow acceptance.

Source review used the skill-source-audit framework with static no-network/no-model scans and manual source adjudication before execution. Whole AI Scientist scanning timed out; narrower agent/script components completed. Some bounded analyzers degraded, and compiled/transitive dependency code was not comprehensively audited. Scanner severity counts alone are not proof of maliciousness or safety. Exact source, artifact hashes, failed attempts, dependency locks and task-private receipts remain with the owning research task. No runtime is activated from a mock, dependency check or transport proof alone.

The shared pinned Headless CLI, `93cd9b06b85f848af1308c41e018991b33907c5e`, was not used unchanged: its default model/provider routing, auth-store staging and paid fallback conflicted with the authorized route. The native transport is a Codex binding around original engine interfaces. Engine selection remains model-agnostic; other host bindings must independently prove actual supported model/effort inheritance and authority instead of inventing defaults.
